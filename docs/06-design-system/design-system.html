Proposed Visual Identity — for approval

The design language of a curated talent agency.

This system is a new proposal — the SRS and PRD specified tone (premium, mobile-first, trustworthy) but no colors, type, or components. Everything below is a concrete design direction for MAYA_X_2.0 to review, not an extraction from existing brand assets. Built to be at home in Next.js + Tailwind CSS + Framer Motion, per the confirmed technology stack.

01 Brand Identity

MAYA_X reads as a confident, unhurried agency — the kind that vets every talent personally and never leaves a client guessing. The identity leans on warm brass rather than loud color, and an editorial serif for moments that need presence, kept next to a plain-spoken sans for everything operational.

Personality

Curated — every talent is vetted; the platform never feels like an open marketplace
Composed — generous whitespace, unhurried pacing, no urgency gimmicks
Discreet — the agency mediates; the UI never rushes a customer toward talent contact
Warm, not cold-corporate — brass and porcelain over blue-and-white SaaS default

Voice & Tone

Plain and specific — "Your request is with our team", never "processing…"
Confident, not salesy — no exclamation marks, no "amazing"
Always names the agency as the actor: "We'll call you within one business day"
Errors state what happened and what to do next — never apologize excessively

Wordmark concept

MAYAX

Serif "MAYA" for editorial warmth, italic brass "X" as the platform's mark — the multiplier standing for the agency's curation layer between customer and talent. Reversible on dark or light grounds; the "X" is the only element permitted in the accent color.

19 Accessibility Guidelines

Proposed baseline (WCAG 2.1 AA) — flagged in the SRS as not client-specified; treat as a recommendation pending confirmation.

  • Contrast: all token pairs in §2 hold 4.5:1 for body text, 3:1 for large text/icons, in both themes.
  • Focus states: every interactive element gets a visible 2px brass outline on keyboard focus (never outline: none without a replacement).
  • Touch targets: minimum 44×44px on mobile, per §16.
  • Forms: every input has a visible, programmatically associated <label> — never placeholder-only; errors are announced via aria-describedby.
  • Status is never color-only: every badge pairs color with a text label and a dot glyph (§12), so status is legible without color perception.
  • Motion: all transitions respect prefers-reduced-motion (§15).
  • Reading order: DOM order matches visual order at every breakpoint — no CSS-only reordering that breaks screen-reader flow.
  • Modals: trap focus while open, return focus to the triggering element on close, dismissible via Esc.
